# W5 — i18n Switcher

**Shipped 2026-08-23.** Small enough that it was built directly rather than planned
first; this is the record.

## The problem

`src/i18n/request.ts:4` was `const locale = "en";` with a comment calling the switch a
"later slice". `messages/es.json` was **1775 leaf keys with zero gaps in either
direction** — verified, not assumed — and completely unreachable.

## What shipped

- `src/lib/i18n/locale.ts` — `LOCALES`, `resolveLocale`, `LOCALE_COOKIE`.
- `src/i18n/request.ts` — resolves per request from the cookie.
- `src/lib/i18n/actions.ts` — `setLocale`, re-resolving before it writes.
- `src/components/settings/LanguageSwitcher.tsx` — rendered on **`/menu`**.
- `tests/unit/locale.test.ts`, `tests/e2e/language-switcher.spec.ts`.

## Three decisions worth keeping

**A cookie, not a profile column.** Public discovery without an account is a locked
strength, so a Spanish-speaking visitor must be able to read the app before they have a
profile to store a preference on. A column serves only signed-in members and needs a
migration. `ponytail: no cross-device sync — add a column when someone asks.`

**The allowlist is a trust boundary.** The resolved locale is interpolated into
`messages/${locale}.json` and the value arrives from a cookie, so an unvalidated locale is
a filesystem path built from user input. `setLocale` re-resolves before writing as well as
on read, because a server action is reachable by direct POST.

**Locales are labelled in their own language.** Someone who needs Spanish cannot
necessarily read the word "Spanish" to find it.

## The mistake the e2e caught

The switcher went onto `/settings` first, carrying a comment arguing it had to be
reachable signed-out — on a page listed in `PROTECTED_PREFIXES`, which redirects
signed-out visitors to `/login`. The argument and the placement contradicted each other in
the same commit.

The e2e caught it only because it browses **signed out on purpose**. A signed-in test
would have passed and shipped a language control invisible to exactly the people who most
need one. Moved to `/menu`, which is public.

## Not done

No profile-level locale, so the choice does not follow a member between devices. No
`Accept-Language` sniffing on first visit — a guess that overrides nothing is harmless,
but a wrong guess on a shared device is annoying, and the control is one tap away.
